# 简历与面试讲解

## 可验证项目描述

**Evidence RAG — 带隔离与引用校验的可信检索工作台**  
技术栈：Python / FastAPI / SQLite / React / TypeScript / pytest / Playwright / GitHub Actions。

构建带文档投毒隔离与证据溯源的 RAG 工作台，实现 BM25 + 字符相似度的 RRF 混合检索、内容寻址版本管理、引用逐字核验与证据不足拒答，并提供可选本地模型适配器。

English summary: A local evidence-first retrieval workbench with BM25, trigram similarity, reciprocal-rank fusion, poisoned-document quarantine and quote verification.

## 讲解顺序

1. 先展示一个失败或攻击场景，说明受保护的资产与信任边界。
2. 运行成功与拒绝路径，展示 API 响应和原始证据。
3. 打开核心模块，解释算法、状态或事务如何保证约束。

## 常见追问

### 为什么引用必须来自本次候选集？

否则模型可以引用其他文档甚至捏造 ID，绕过检索权限与证据选择。校验器使用本次候选白名单并验证原文子串。

### RRF 为什么适合组合两个分数？

BM25 与余弦分数尺度不同；RRF 使用排名而非直接相加。这里采用 k=60，但应通过隔离验证集选择参数。

### 为什么没有向量数据库？

当前规模先建立可解释基线；是否引入向量索引应由召回质量和语料规模驱动，而不是为技术栈堆叠。

## 诚实使用

- 项目属于 AI 应用安全与 Agent 安全工程，不等同于大模型预训练、对齐或安全研究成果。
- 可以写真实实现和通过的测试数量；不能虚构用户量、生产 QPS、降低风险百分比或企业落地经历。
- 此初版使用 AI 辅助开发。亲自复现、修改并解释关键模块后再作为自己的面试项目展开。
- 性能或防御效果必须带上数据集版本、样本数、运行环境与测量方法。
